# One-Time-Off Platform integration — Phase 1

App ID: `one-time-off`. Independent repository: `ivancww/one-time-off`; App changes continue in PR #1. Platform baseline: `ivancww/avaplatform` main `a12beaea002df9ae13e676f890c16951d4f21b28`, including `AGENTS.md`, `docs/MOTHER-RULES.md` and the canonical Design System. This record is not full Mother Standard compliance certification.

The app's `?avaEntry=frontend` is the sales presentation. `?avaEntry=user` edits that same presentation, provides draft preview and Save Local, and retains v1–v5 backup compatibility and historical custom pages. Official refresh and User overrides use separate IndexedDB databases. The persistent Return to AVA control targets the existing Platform destination `https://ivancww.github.io/avaplatform/`, with `?avaSurface=user` for User Edit and its preview. Preview uses the draft without saving it. It does not create a second workspace. Calculations and GAS integration are outside this integration change.

No canonical One-Time-Off deployment URL or production App origin has been verified. App main still contains only initialization content; the implementation is unmerged in PR #1. Platform registration therefore uses the existing `deployment-pending` state, with no invented entry URLs, disabled/hidden registration, frontend capability declared, user capability held false pending deployed validation, and admin false. Local integration QA temporarily supplies loopback URLs and user capability in memory only, exercises the registry's existing navigation, and redirects only the test browser's Return-to-AVA request to local Platform. This is not production or physical-device evidence. Platform's installed/standalone state is simulated for the launch/return test; real installed-PWA verification remains open.

Before activation: Owner-approved App merge/deployment, verified canonical App URL/origin, live Front and User entry/preview/save/reopen/return tests, backups and Official/User separation, PWA/shell lifecycle, physical iPad and HONOR Magic V5/WebView checks. Then a reviewed Platform update may add verified entry URLs, enable User capability and visibility. No production hosting, DNS or authentication change is authorized by this PR.

## Admin Phase 2 reservation

Admin capability remains false. `?avaEntry=admin` renders a safe unavailable state; the query is never authorization. Permitted production App origins are **not configured** because the deployment origin is unverified. The future App ID is `one-time-off`; its actual HTTPS origin must be verified before any Platform or server allowlist is changed. No admin ticket handler, password, fake grant or second authentication system is included.

Future Admin must implement the Platform's `ava-admin-session-v1` contract: a valid AVA Studio Admin session, App-bound one-time ticket and nonce, retained-opener browser proof, strict Platform/App origin and ID validation, expiry, server-side exchange, one-time consumption and replay rejection. Official reads/writes must be authorized server-side; UI flags, URL parameters and referrers are insufficient. Only Official configuration belongs to Admin; User presentation overrides remain local and protected calculations/data remain App-owned. Review the then-current Platform `docs/ava-studio-admin-authentication.md` and readiness gates before Phase 2. No production auth configuration or secrets are changed now.
